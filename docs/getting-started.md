# Getting Started with Hawk

This guide walks you through creating your first Hawk application, configuring it, creating routes, working with the database, running migrations, seeding data, and testing your application.

## Prerequisites

Before using Hawk, make sure you have:

* Go installed
* A supported database configured for your application
* Basic knowledge of Go
* A terminal or command prompt

Check your Go installation:

```bash
go version
```

---

## 1. Install the Hawk CLI

Install the Hawk CLI using Go:

```bash
go install github.com/beyond3800/hawk/cmd/hawk@latest
```

Verify that Hawk is available:

```bash
hawk --help
```

You should see the available Hawk commands.

---

## 2. Create a New Application

Create a new Hawk application with:

```bash
hawk new blog
```

This creates a new project named `blog`.

Move into the project:

```bash
cd blog
```

Your project will contain the basic structure required to start developing your application.

---

## 3. Start the Application

Run the Hawk development server:

```bash
hawk serve
```

Hawk will build and start the application.

You can now open your application in a browser or send a request using an HTTP client.

---

## 4. Project Structure

A typical Hawk application contains directories similar to:

```text
blog/
├── app/
├── bootstrap/
├── commands/
├── config/
├── database/
│   ├── migrations/
│   └── seeders/
├── routes/
├── storage/
├── .env
├── go.mod
└── main.go
```

The exact structure may change as Hawk evolves.

The important idea is that Hawk separates application code from framework infrastructure so that your project remains organized as it grows.

## 5. Create Your First Route

Hawk routes are registered using the router.

For example:

```go
router.Get("/hello", func(c *hawk.Context) {
    c.String(200, "Hello from Hawk!")
})
```

Start your application and request:

```text
GET /hello
```

The server responds with:

```text
Hello from Hawk!
```

---

## 6. Route Parameters

Hawk supports dynamic route parameters.

```go
router.Get("/users/:id", func(c *hawk.Context) {
    id := c.Param("id")

    c.JSON(200, map[string]any{
        "id": id,
    })
})
```

A request to:

```text
/users/123
```

returns:

```json
{
    "id": "123"
}
```

You can also use multiple parameters:

```go
router.Get(
    "/users/:userID/posts/:postID",
    func(c *hawk.Context) {

        userID := c.Param("userID")
        postID := c.Param("postID")

        c.JSON(200, map[string]any{
            "user_id": userID,
            "post_id": postID,
        })
    },
)
```

---

## 7. Query Parameters

Query parameters can be accessed with `Query()`.

For a request such as:

```text
/users?page=2&limit=10
```

you can retrieve the values:

```go
page := c.Query("page")
limit := c.Query("limit")
```

Both values are returned as strings.

---

## 8. Middleware

Middleware allows you to execute logic before a route handler.

For example:

```go
router.Use(func(c *hawk.Context) {

    // middleware logic

    c.Next()
})
```

Middleware can stop request execution using `Abort()`:

```go
router.Use(func(c *hawk.Context) {

    if !authenticated {
        c.Abort()
        return
    }

    c.Next()
})
```

This allows you to implement things such as:

* Authentication
* Authorization
* Logging
* CORS
* Request processing
* Error handling

See the middleware documentation for more information.

## 9. Configure the Database

Configure your application's database connection using the environment configuration provided by the generated application.

Your `.env` file may contain values such as:

```env
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=blog
DB_USERNAME=root
DB_PASSWORD=
```

Use the configuration generated by your version of Hawk rather than copying variables that aren't present in your project.

---

## 10. Create a Migration

Use the Hawk CLI to create a migration:

```bash
hawk make migration create_users_table
```

Implement the schema changes inside the generated migration.

For example, a migration may create a users table containing:

```text
id
name
email
password
created_at
updated_at
```

Run the migration:

```bash
hawk migrate
```

Hawk records executed migrations so they aren't repeatedly executed.

## 11. Database Queries

Hawk provides a query builder for interacting with your database.

Create a record:

```go
result, err := HawkDB().
    Table("users").
    Create(map[string]any{
        "name":  "Adam",
        "email": "adam@test.com",
    })

if err != nil {
    return err
}
```

Retrieve records:

```go
var users []User

err := HawkDB().
    Table("users").
    Get(&users)

if err != nil {
    return err
}
```

Retrieve the first record:

```go
var user User

err := HawkDB().
    Table("users").
    First(&user)
```

---

## 12. Pagination

Hawk provides pagination through the query builder.

```go
var users []User

result, err := HawkDB().
    Table("users").
    Paginate(1, 10, &users)

if err != nil {
    return err
}
```

The first argument is the page number and the second is the number of records per page.

Pagination metadata can be accessed through:

```go
result.Meta.Total
result.Meta.PerPage
```

---

## 13. Database Transactions

Use transactions when multiple database operations must succeed or fail together.

```go
err := HawkDB().Transaction(func(tx *Builder) error {

    _, err := tx.Table("users").Create(map[string]any{
        "name":  "Adam",
        "email": "adam@test.com",
    })

    if err != nil {
        return err
    }

    _, err = tx.Table("wallets").Create(map[string]any{
        "user_id": 1,
        "balance": 0,
    })

    if err != nil {
        return err
    }

    return nil
})
```

If the callback returns an error, Hawk rolls back the transaction.

If the callback returns `nil`, the transaction is committed.

## 14. Create Seed Data

Hawk applications can use seeders to populate databases with initial or development data.

Run the application's database seed command:

```bash
hawk db seed
```

Seeders are useful for:

* Development data
* Initial application records
* Test data
* Local development environments

---

## 15. Factories

Factories provide a convenient way to generate test and development data.

Create a factory using:

```bash
hawk make factory User
```

Hawk provides built-in faker functionality for generating realistic random values.

For example, a factory can generate values such as:

```text
Name
Email
Password
Phone number
Address
```

If the built-in faker functionality doesn't provide what your application needs, you can use another faker package.

---

## 16. Validation

Hawk currently provides these validation rules:

```text
required
email
min
max
```

A validation definition may look like:

```go
Name     string `validate:"required|min:3|max:50"`
Email    string `validate:"required|email"`
Password string `validate:"required|min:8"`
```

Validation errors are stored in Hawk's validation error structure.

---

## 17. Testing

Hawk applications use Go's standard testing system.

Run all tests:

```bash
go test ./...
```

Run tests for a specific package:

```bash
go test ./database
```

Run a specific test:

```bash
go test ./database -run TestCreate
```

Run static analysis:

```bash
go vet ./...
```

Build the project:

```bash
go build ./...
```

Before committing changes, it is recommended to run:

```bash
go test ./...
go vet ./...
go build ./...
```

## 19. Development Workflow

A typical Hawk development workflow looks like:

```text
Create application
       ↓
Configure environment
       ↓
Create migration
       ↓
Run migration
       ↓
Create routes
       ↓
Create application logic
       ↓
Add validation
       ↓
Create factories/seeders
       ↓
Write tests
       ↓
Run tests
       ↓
Build application
       ↓
Deploy
```

For example:

```bash
hawk new blog

cd blog

hawk migrate

hawk db seed

hawk serve
```

Then during development:

```bash
go test ./...
go vet ./...
go build ./...
```
